# VisitAl Core

افزونه‌ی اختصاصی منطق کسب‌وکار سامانه‌ی نوبت‌دهی VisitAl روی قالب Dr Plus. تمام قابلیت‌ها بدون دستکاری هسته‌ی قالب و از طریق هوک‌ها/فیلترها و اورراید چایلد‌تم پیاده شده‌اند تا با آپدیت قالب چیزی خراب نشود.

## قابلیت‌های کدشده (آماده)

### اولین نوبت خالی (کارت پزشکان)
- سرویس کش‌شده‌ی `Visital_Availability` نزدیک‌ترین زمان خالی هر پزشک را محاسبه می‌کند (با بای‌پس سریع برای پزشکان بدون شیفت فعال، مناسب مقیاس ۱۰۰۰ پزشک).
- برچسب روی کارت از طریق `visital_next_slot_badge( $specialist )` در اورراید کارت چایلد‌تم.
- فیلترها: `visital/next_slot/show_empty`, `visital/next_slot/badge_html`.

### ظرفیت خالی روزانه روی تقویم نوبت‌دهی
- اندپوینت ایجکس `visital_day_capacity` تعداد نوبت خالی هر روز را با کش برمی‌گرداند.
- بج روی سلول‌های تقویم با `assets/js/visital-calendar.js` تزریق می‌شود (ناوبری ماه با MutationObserver).

### رفع باگ تقویم شمسی
- هماهنگ‌سازی حالت کبیسه‌ی دیتاپیکر فرانت (`leapYearMode`) با مبدل JDF بک‌اند، برای رفع تکرار روزهای آخر ماه.

### امتیازدهی چندمعیاره
- شش معیار پیش‌فرض، قابل ویرایش از پیشخوان: تنظیمات → «معیارهای امتیازدهی».
- امتیاز هر معیار در متای کامنت `visital_rating_{key}` ذخیره و امتیاز کلی در سیستم موجود قالب به‌روزرسانی می‌شود (گیتِ «بیمار تاییدشده» حفظ شده).
- نمایش میانگین کل و تفکیکی (ستاره + میله) در پروفایل، از طریق اورراید `template-specialists-single-reviews.php`.
- فیلتر معیارها: `visital/review/criteria`.

### فیلتر خدمات/علائم و محله
- جستجوی دایرکتوری علاوه بر نام و تخصص، خدمات اعلام‌شده‌ی پزشک (`meta.services`) را هم می‌یابد.
- فیلتر «محله/منطقه» بر پایه‌ی زیرترم‌های تاکسونومی سلسله‌مراتبی `location`؛ در فرم دایرکتوری با انتخاب شهر ظاهر می‌شود.
- برای فعال‌شدن محله‌ها: در «نوشته‌ها/تخصص‌ها → تاکسونومی location» برای هر شهر، ترم‌های فرزند (محله‌ها) بسازید و به پروفایل/مطب پزشکان اختصاص دهید.

### ادعای پروفایل با کد نظام پزشکی + OTP
- گیت ابتدای onboarding (`Visital_Claim`): پزشک کد نظام را وارد می‌کند؛ اگر در دیتابیس بود نمایش و با تایید، همان پروفایل به حساب او متصل می‌شود؛ اگر نبود، پروفایل جدید.
- تایید شماره با OTP (زیرساخت پیامک/OTP قالب).
- اتصال مالکیت با گارد در برابر قید یکتای `user_id`؛ در هر حالت مبهم به‌جای دستکاری داده، فلگ «اتصال دستی توسط ادمین» (`visital_claim_pending_link`) ست می‌شود.
- آپلود مدارک (کارت ملی + پروانه/کارت نظام) و تایید نهایی توسط ادمین، همان مرحله‌ی identity و تایید موجود قالب است که گیت واقعی فعال‌سازیِ نوبت‌دهی است.
- یادداشت: به‌خاطر اینکه OTP به شماره‌ی واردشده می‌رود، تایید مدارک توسط ادمین مرز امنیتی اصلی است. مرحله‌ی «اتصال مالکیت» را حتماً یک‌بار روی استیجینگ با یک کد نظام واقعی تست کنید.

### هوک‌های تماس امن (Call Masking)
- API فیلتری `Visital_CallMask::display_number()` و `visital/call_mask/number`, `visital/call_mask/create_session`.
- اندپوینت کال‌بک امضاشده: `visital/v1/call-mask/callback`.
- تنظیمات: تنظیمات → «تماس امن (VisitAl)».

## کارهای باقی‌مانده که روی سایت زنده کانفیگ می‌شوند (نه کد)

### درگاه پرداخت (#۶)
از طریق تنظیمات WooCommerce / افزونه‌ی درگاه خریداری‌شده کانفیگ شود؛ سپس تراکنش موفق و ناموفق تست شود.

### پنل پیامکی و پترن‌ها (#۷)
در تنظیمات پیامک قالب، درگاه (Melipayamak یا Farazsms/ippanel) و کلید API را وارد کنید و کد پترن و متن هر رویداد را برای بیمار و پزشک تنظیم کنید:
- احراز هویت: login / register / lost_password (OTP)
- رزرو: تایید، یادآوری (زمان‌بندی چندگانه با کرون `CheckBookingMessages`)، لغو/تغییر — برای بیمار و پزشک.

### اسکای‌روم (#۸)
کلید API اسکای‌روم را در تنظیمات قالب وارد کنید (ساخت اتاق و ارسال لینک از پیش پیاده شده است: اکشن `skyroom_get_room_link`).

### بیعانه/کارمزد/تسهیم (#۵)
ستون‌های `commission` و `specialist_income` و `WalletUtils` موجودند. مبلغ بیعانه و درصد کارمزد و تسهیم باید در مسیر ساخت سفارش/پرداخت و روی درگاه تسهیم کانفیگ و تست شود (نیازمند درگاه و تست زنده).

### بهینه‌سازی هاست/کش (#۱۳)
افزونه‌ی LiteSpeed Cache نصب است؛ فعال‌سازی کش صفحه + Object Cache با Redis و تست فشار روی سرور انجام می‌شود.
